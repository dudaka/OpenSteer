# Rust + React re-implementation plan

Goal: re-implement OpenSteer steering behaviors in Rust, with a React page demonstrating each
behavior. Stage 1 is 2D. Each step is small and ends with a check.

Later stage (not planned yet): research 2.5D / 3D with terrain and navmesh.

## Setup, mirrored from `~/Workspace/silkroad/caravan`

The new code lives in this repo next to the C++ reference (`crates/`, `packages/`, `apps/`).

```
Cargo.toml              workspace, members = ["crates/*"], [workspace.package] edition 2021,
                        rust-version 1.90, lints: unsafe_code forbid, clippy all warn
rust-toolchain.toml     stable + rustfmt, clippy
rustfmt.toml            edition = "2021"
.cargo/config.toml      [env] TS_RS_EXPORT_DIR = packages/core/src/contract (relative)
package.json            npm workspaces ["packages/*", "apps/*"]; build / dev / typecheck scripts
tsconfig.base.json      copied from caravan (ES2022, Bundler, strict, react-jsx)
.github/workflows/ci.yml  fmt, clippy -D warnings, test, contract diff; npm ci, typecheck, build

crates/steer-core       L1 pure 2D math + vehicle + behaviors. No tokio, no serde, no IO.
crates/steer-demos      L2 one module per demo (the C++ plug-ins): world setup, update(dt),
                        and its view model (serde + ts-rs). No tokio.
crates/steerd           L3 daemon: axum 0.8 (ws), tokio, rmp-serde, tower-http ServeDir.
                        contract.rs: Request { id, call }, Call (tag "method"/content "params"),
                        Reply (tag "type"/content "value"), HostFrame (tag "t").
                        Runs the fixed-step sim loop, broadcasts frames, serves apps/web/dist.
                        Port 7400 (caravand uses 7300).

packages/core           @opensteer/core: MessagePack transport (@msgpack/msgpack) over a
                        WebSocket Link with reconnect, Host class with typed calls, Redux
                        Toolkit store whose reducers only copy what steerd sent, generated
                        contract types in src/contract/ (committed, never hand-written).
apps/web                @opensteer/web: React 19 + Vite + react-redux; Vite proxies /ws to
                        127.0.0.1:7400. Drawing with three.js (as caravan), orthographic top-down camera on the XZ ground plane, so 2.5D/3D later only changes the camera and adds height.
```

Rules carried over from caravan:
- A crate depends only on crates below it (core <- demos <- steerd).
- **Frontend is dumb**: all steering math and annotations (velocity, force, predicted target,
  neighbor radius) are computed in Rust into view models. The browser draws them and sends
  typed commands (select demo, play/pause/step/reset, set parameter, move target). Only
  visual interpolation between two frames is allowed client-side.
- Contract types are generated by `ts-rs` on `cargo test`; CI fails if they differ.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `npm run typecheck`
  green before a commit. Errors: `thiserror` in libs, `anyhow` only in `steerd`. Logging: `tracing`.
- Pin exact npm versions (caravan pins exact versions).

Commands (once Phase 0 exists):
```
cargo test                              # all Rust tests, regenerates contract types
cargo test -p steer-core seek           # one test by name filter
cargo run -p steerd                     # http://127.0.0.1:7400 (serves apps/web/dist)
npm install && npm run dev              # Vite on :5173, proxies /ws to steerd
npm run build && npm run typecheck
```

## Phase 0 - skeleton

1. [done] Workspace files above + empty `steer-core`, `steer-demos`, `steerd`. -> verify: `cargo test`, `cargo clippy -- -D warnings`. (CI has the rust job only; the web job is added in step 3.)
2. [done] `steerd` serves `/ws`; contract with one call `demo.list` (`HostFrame::Res` only; the sim frame variant comes in step 4). `cargo test` writes TS types. -> verify: types appear in `packages/core/src/contract/`; a msgpack WebSocket client gets the demo list.
3. [done] `packages/core` transport + store, `apps/web` shows connection status and the demo list. -> verify: browser shows "connected" and the list.
4. [done] Sim loop: steerd ticks a fixed 60 Hz step, sends one hard-coded dot per frame; a three.js scene draws it. -> verify: moving dot.

## Phase 1 - vehicle and integrator (`src/SimpleVehicle.cpp`)

5. [done] `Vec2` (`length`, `normalize`, `truncate_length`, `dot`, `perp`, parallel/perpendicular components) + `util` (`interpolate`, `blend_into_accumulator`, `limit_max_deviation_angle`). `rotate`/`distance` come when a behavior needs them. -> verify: unit tests.
6. [done] `Vehicle { position, forward, speed, mass, radius, max_force, max_speed, smoothed_acceleration }` (C++ keeps forward + speed, velocity = forward * speed) and `apply_steering_force(force, dt)` ported from `applySteeringForce` incl. `adjustRawSteeringForce`. -> verify: property tests + `tests/oracle_one_turning.rs` matches the C++ `SimpleVehicle` (`oracle/one_turning.cpp`) to 1e-4 over 600 steps.
7. [done] Demo "One Turning" (`plugins/OneTurning.cpp`): constant force, trail, velocity/accel annotation lines. -> verify: smooth arc in browser, matches C++ demo visually. Camera follows the vehicle (Rust sends `focus`); no reset control yet, so it runs off in a straight line once at max speed.

## Phase 2 - single-target behaviors (`include/OpenSteer/SteerLibrary.h`)

8. Seek and Flee (port `xxxsteerForSeek/Flee`). Demo: target follows mouse click.
9. Arrive (classic Reynolds, not in OpenSteer) - slow inside a radius. Same demo, toggle.
10. Wander (`steerForWander` + `scalarRandomWalk`) plus `steerForTargetSpeed`.
11. Pursuit (9-case time-factor table) and Evasion. Demo: `MultiplePursuit` - one wanderer, several pursuers, colored prediction lines.
- verify each: unit test on force direction + demo page with parameter sliders.

## Phase 3 - environment

12. Circle obstacles + `steer_to_avoid_obstacles` (`src/Obstacle.cpp`). Demo: wanderer among obstacles, show the probe and the chosen obstacle.
13. Polyline pathway with radius (`PolylineSegmentedPathwaySingleRadius`): `map_point_to_path`, `map_path_distance_to_point`. -> verify: tests mirroring `test/PolylineSegmentedPath*Test.cpp`.
14. Path following and stay-on-path. Demo: figure-eight (`plugins/PedestriansWalkingAnEight.cpp`).

## Phase 4 - groups

15. Neighbor query: brute force first, then a uniform grid (role of `src/lq.c`). -> verify: grid equals brute force in a test.
16. Separation, Alignment, Cohesion (`inBoidNeighborhood`). Demo: Boids (`plugins/Boids.cpp`) with weight sliders and wrap-around.
17. Neighbor avoidance (`steerToAvoidNeighbors`, nearest approach). Demo: pedestrians crossing.

## Phase 5 - composite demos (optional)

18. Capture the Flag (seek home, evade defenders, braking).
19. Pedestrians (path + obstacles + neighbors).
20. Soccer.

## Each demo page

three.js view, play/pause/step/reset, parameter sliders, toggles for each annotation. Demos are listed
in a sidebar, mirroring OpenSteerDemo's plug-in selection.
